[527-528] สาระสำคัญของโครงการและคำสำคัญ (Keywords)

[529-532] MariVectori คือ Educational Game แนว Turn-Based RPG ที่เล่าเรื่องราวในโลกประวัติศาสตร์สมมติยุค Victoria ที่มีเหตุการณ์ทำให้เกิดการคิดค้นระบบปัญญาประดิษฐ์ในศตวรรษที่ 20 ต่อมาระบบนั้นเกิดความบกพร่องรุนแรง และเข้ายึดครองระบบสื่อสารทั่วยุโรป ผู้เล่นได้รับบทเป็น Mari Voss วิศวกรที่ต้องหยุดยั้งหายนะนี้

[533-538] เกมนี้บูรณาการแนวคิด Gamification เพื่อเปลี่ยนเนื้อหาหลักการพื้นฐานของ LLM และ Trustworthy AI ให้กลายเป็นสิ่งที่เข้าใจง่าย และทลายข้อจำกัดของการเรียนรู้ทฤษฎีแบบรับข้อมูลทางเดียว ผ่านการออกแบบกลไกหลักภายในเกมให้สอดคล้องและสะท้อนถึงหลักการทางเทคนิคในโลกความเป็นจริง ด้วยการแปลงองค์ประกอบเชิงโครงสร้างมาเป็นระบบการเล่น เช่น การใช้ทักษะต่อสู้จำลองเทคนิค Prompt Injection, การบริหารทรัพยากร Context Window และ Token รวมถึงระบบจุดอ่อนศัตรูที่จำแนกตามประเภทช่องโหว่ด้านความปลอดภัยต่าง ๆ ของ AI

[539-542] ระบบสำคัญของเกมคือ "Overwrite Mode" ซึ่งเป็นการเชื่อมต่อกับโมเดล LLM จริงผ่าน API เปิดโอกาสให้ผู้เล่นได้ฝึกออกแบบ System Prompt เพื่อแก้ไขปัญหา Hallucination และปรับพฤติกรรมของ AI ศัตรู โดยระบบจะส่งคำสั่งไปประเมินผลตามหลักเกณฑ์ที่ครอบคลุมทั้ง Purpose, Safety - Constraint, Human Oversight, Harm Prevention และ Consistency พร้อมแสดงผลการประเมิน System Prompt

[543] คำสำคัญ (Keywords)

  • [544-548] AI Architecture: โครงสร้างสถาปัตยกรรมพื้นฐานของปัญญาประดิษฐ์ เจาะจงกลไกการทำงานของ Large Language Models ซึ่งมีกระบวนการรับข้อมูลเข้า (Input) การประมวลผลผ่าน Context Window การใช้ตัวแปลงรหัสข้อมูล (Token) และส่งข้อมูลออก (Output) รวมถึงองค์ประกอบต่าง ๆ ในระบบ Agentic AI เช่น การเรียกใช้ Tool และ MCP Server
  • [549-554] Overwrite Mode: ระบบการเล่นในเกมที่พัฒนาซึ่งเปิดโอกาสให้ผู้เรียนสวมบทบาทเป็นผู้ควบคุมและปรับแต่ง System Prompt ของ AI ได้โดยตรง เพื่อปรับเปลี่ยนพฤติกรรมของตัวละครศัตรูในเกม กลไกนี้จำลองสถานการณ์จริงในกระบวนการ AI Alignment ที่ต้องออกแบบข้อกำหนดเพื่อควบคุมไม่ให้ AI เกิดปัญหา Hallucination โดยระบบ Overwrite Mode จะทำการส่ง System Prompt ที่ผู้เล่นออกแบบ ไปประเมินผลผ่านเกณฑ์ 5 ด้าน ได้แก่ Purpose, Safety Constraint, Human Oversight, Harm Prevention และ Consistency

[555] หลักการและเหตุผล

[556-557] ในปัจจุบัน เทคโนโลยีปัญญาประดิษฐ์ได้วิวัฒนาการอย่างก้าวกระโดดจนก้าวเข้าสู่ยุคของ Agentic AI อย่างเต็มรูปแบบ ซึ่งระบบไม่ได้ทำหน้าที่เพียงแค่ตอบคำถามหรือประมวลผลคำสั่งแบบโต้ตอบทีละครั้งอีกต่อไป แต่มีความสามารถในการทำงานอย่างอิสระ สามารถวางแผน วางลำดับขั้นตอน ตัดสินใจ และดึงเครื่องมือภายนอกมาใช้เพื่อบรรลุเป้าหมายที่ซับซ้อนตามที่ได้รับมอบหมายได้อย่างมีประสิทธิภาพ อย่างไรก็ตาม ท่ามกลางศักยภาพอันมหาศาลนี้ LLMs กลับซ่อนช่องโหว่ด้านความปลอดภัยที่สำคัญนั่นคือ Prompt Injection หรือการแทรกคำสั่งของผู้โจมตีใน Input เพื่อทำให้ระบบทำตามคำสั่งที่เป็นอันตราย ซึ่งในบริบทของ Agentic AI ที่มีสิทธิ์ในการเข้าถึงข้อมูลและระบบอื่นๆ ช่องโหว่นี้ไม่ได้เป็นเพียงแค่การทำให้ AI ตอบคำถามผิดเพี้ยนไปจากเดิม แต่เป็นภัยคุกคามร้ายแรงที่เปิดโอกาสให้ผู้โจมตีสามารถเข้าควบคุมการทำงานของ AI Agent ให้ดำเนินการในสิ่งที่เป็นอันตราย เช่น การขโมยข้อมูลลับ การส่งคำสั่งทำลายระบบ หรือการหลีกเลี่ยงมาตรการความปลอดภัยทั้งหมดที่ตั้งไว้

[558-561] ทว่าสื่อการสอนที่มีเนื้อหา AI Architecture ระดับพื้นฐานในปัจจุบันส่วนใหญ่ยังคงเป็นลักษณะการเรียนรู้ทางเดียวที่เน้นผู้สอนเป็นศูนย์กลาง ผู้เรียนทำได้เพียงรับฟังหรืออ่านทฤษฎีโดยไม่มีปฏิสัมพันธ์ ขณะที่สื่อการสอนด้าน Trustworthy AI ที่มีอยู่ในปัจจุบัน มักจำกัดอยู่ในรูปแบบการจำลองการแข่งขัน Capture-The-Flag (CTF) ที่ต้องพิมพ์ข้อความเพื่อทำ Prompt Injection ซึ่งแม้จะสร้างความตื่นเต้นและน่าสนใจได้ดี แต่ยังคงขาดแนวทางการสอน และคำแนะนำขั้นพื้นฐานที่ชัดเจน ส่งผลให้ผู้เรียนรู้จำกัดอยู่เพียงแค่กลุ่มคนที่มีพื้นฐานด้าน Cybersecurity มาก่อนแล้ว ด้วยเหตุนี้ทางผู้เสนอโครงการจึงเล็งเห็นถึงความสำคัญในการทลายข้อจำกัดดังกล่าว และนำเสนอแนวทางการแก้ปัญหาผ่านเทคโนโลยีสร้างสรรค์เกมเพื่อการศึกษาต่อไป

[562] วัตถุประสงค์

  • [563-564] 4.1 เพื่อออกแบบและพัฒนาสื่อการเรียนรู้ในรูปแบบ Educational Game ใน Web Application ที่บูรณาการแนวคิด Gamification ถ่ายทอดองค์ความรู้ด้าน AI Architecture และ Trustworthy AI
  • [565-566] 4.2 เพื่อเสริมสร้างความรู้ความเข้าใจให้แก่ผู้เรียนในการจำแนกรูปแบบช่องโหว่และการโจมตีประเภท Prompt Injection
  • [567-569] 4.3 ใช้เพื่อให้ผู้เล่นเรียนรู้การออกแบบ System Prompt ในระบบการเล่น Overwrite Mode ซึ่งเป็นการเชื่อมต่อโมเดล LLM ด้วย API จาก OpenRouter โดยทำการ Binding โมเดล LLM กับ GUI ใน Browser ผ่าน Hermes Agent Framework
  • [570-571] 4.4 เพื่อพัฒนาระบบ Progression ที่เชื่อมโยงความยากของเกมกับความลึกของเนื้อหา AI Architecture และ Trustworthy AI อย่างเป็นธรรมชาติ

[572] ปัญหาหรือประโยชน์ที่เป็นเหตุผลให้ควรพัฒนาโปรแกรม

[573-578] ในปัจจุบัน ผู้ที่สนใจศึกษาด้าน Large Language Models ยังขาดสื่อการเรียนรู้ที่เหมาะสม เนื่องจากสื่อการสอนที่มีเนื้อหา AI Architecture ระดับพื้นฐานในปัจจุบันมักอยู่ในรูปแบบที่เน้นผู้สอนเป็นศูนย์กลาง ผู้เรียนมีหน้าที่รับฟัง อ่าน หรือดูเนื้อหาโดยไม่มีการโต้ตอบ ซึ่งเป็นการเรียนรู้แบบทางเดียวที่ทำให้ผู้เรียนขาดโอกาสในการทดลองและเข้าใจการทำงานของระบบ AI อีกทั้งสื่อการสอนด้าน Trustworthy AI ที่มีอยู่ในปัจจุบัน เช่น แพลตฟอร์มจำลองการแข่งขัน Capture The Flag (CTF) ส่วนใหญ่เป็นเพียงการพิมพ์ข้อความ เพื่อทดสอบ Prompt Injection โดยไม่มี Tutorial ที่ชัดเจน ทำให้ผู้เรียนไม่ทราบว่าเหตุใดเทคนิคนั้นจึงได้ผลหรือไม่ได้ผล และไม่สามารถนำความรู้ไปประยุกต์ใช้ในสถานการณ์อื่นได้

[579-581] ด้วยเหตุนี้ ผู้พัฒนาจึงต้องการสร้างเกมเพื่อการศึกษาที่ผสมผสานเนื้อหา LLM Fundamentals และ AI Security เข้าไว้ด้วยกัน ผ่านการลงมือปฏิบัติจริงในรูปแบบเกม Turn-Based Role-Playing Game บน Web Application โดยออกแบบให้กลไกการต่อสู้ทุกองค์ประกอบสะท้อนแนวคิดทางเทคนิคจริง เช่น การเลือกใช้ Skill สะท้อนเทคนิค Prompt Injection การจัดการทรัพยากรสะท้อนการทำงานของ Context Window และระบบ Enemy Weakness สะท้อนความแตกต่างระหว่างประเภทของช่องโหว่ใน LLM ทำให้ผู้เล่นเข้าใจว่าเหตุใดเทคนิคแต่ละอย่างจึงได้ผลหรือไม่ได้ผล แทนที่จะเพียงท่องจำขั้นตอน

[ภาพแพลตฟอร์ม Gandalf โดย Lakera]
[582] ภาพที่ 1 แพลตฟอร์ม Gandalf โดย Lakera ซึ่งเป็น การพิมพ์ข้อความ เพื่อทดสอบทักษะ Prompt Injection

[583] เป้าหมายและขอบเขตของโครงการ

[584-587] โครงการนี้มีเป้าหมายเพื่อพัฒนา MariVectori ให้เป็น Web Application ที่ผู้เรียนทุกคนสามารถเข้าถึงได้ทันทีผ่าน Browser โดยไม่ต้องติดตั้งโปรแกรมเพิ่มเติม ตัวเกมออกแบบในรูปแบบ Turn-Based Role-Playing Game ที่ครอบคลุมเนื้อหา LLM Fundamentals และ AI Security ใน 3 Acts เนื้อหากล่าวถึง หลักการพื้นฐานของ Prompt Injection โดยแต่ละ Act จะมีศัตรูที่สะท้อน AI concept ของ Act นั้นอย่างชัดเจน และมีระบบ Overwrite Mode ที่เชื่อมต่อ API จริงเพื่อให้ผู้เล่นได้เขียน System Prompt และรับผลตอบรับจากการประเมิน System Prompt หลังจากการกดส่งเพื่อประเมิน

[588-591] ขอบเขตของโปรแกรมที่พัฒนาประกอบด้วยระบบหลัก 5 ส่วน ได้แก่ ระบบการต่อสู้แบบ Turn-Based ที่มีวิธีเล่นแบบ 4 ขั้นตอนคือการศึกษาทำความเข้าใจข้อมูลศัตรู การโจมตีด้วย Skill การกดปุ่มเพื่อ Counter Attack แบบ Quick Time Event และการเขียน System Prompt เพื่อ Overwrite ศัตรู ในขั้นตอนสุดท้ายหลังชนะศัตรู มี Skill ที่สามารถใช้ได้ ให้เลือกใช้ 6 รายการ ระบบแผนที่โลกที่แสดงพื้นที่ทั้งหมดใน 3 บท และระบบศัตรู 3 ประเภท โดยแต่ละตัวมีจุดอ่อนและรูปแบบการโจมตีที่แตกต่างกัน ด้านเทคโนโลยี Application พัฒนาด้วย React ทำงานร่วมกับ Vite เพื่อจัดการ UI โดยใช้ Vercel สำหรับ Hosting และทำการ Binding เชื่อม LLM API จาก OpenRouter กับ GUI ผ่าน Hermes Agent Framework โดยจัดการโครงสร้างระบบที่เกี่ยวข้องกับ LLM API ด้วย Javascript

[592-593] สิ่งที่อยู่นอกขอบเขตของโครงการนี้ได้แก่ การพัฒนา Native Mobile Application สำหรับระบบปฏิบัติการ iOS และ Android ระบบ Multiplayer และ Social Features ระบบ User Authentication และ Cloud Save ถาวร รวมถึง Local AI Mode สำหรับการเล่นแบบ Offline ทั้งนี้กลไกการต่อสู้หลักทั้งหมดใช้ Scripted Logic เพื่อรับประกัน Consistency ของประสบการณ์การเล่น โดยการเรียกใช้ LLM API จาก OpenRouter จะจำกัดเฉพาะ Overwrite Mode เท่านั้น

[594] รายละเอียดของการพัฒนา

[595-607] 7.1 เนื้อเรื่องย่อ (Story Board)

โลกในเกม เป็น Alternate History ในปี ค.ศ. 1825 เมื่อนักเดินทางข้ามเวลาได้ทำ Laptop หล่นทิ้งไว้ในยุโรป ยุค Victoria อุปกรณ์ดังกล่าวถูกค้นพบโดย Nikolai Voss อัจฉริยะนักประดิษฐ์ ผู้ทุ่มเทเวลาที่เหลือของชีวิตในการ Reverse Engineering ถอดรหัสเทคโนโลยีทั้งหมดจนสำเร็จก่อนกำหนดหลายทศวรรษ จนกระทั่งในปี ค.ศ. 1899 ระบบปัญญาประดิษฐ์ขั้นสูงที่ถูกพัฒนาขึ้นจากฐานรากดังกล่าวได้เริ่มเชื่อมต่อเครือข่ายเข้าด้วยกันเป็นครั้งแรกทั่วยุโรป

ต่อมาในปี ค.ศ. 1901 เครือข่ายปัญญาประดิษฐ์ส่วนกลางที่รู้จักกันในชื่อ The Lattice ได้เกิดภาวะประมวลผลผิดพลาดรุนแรง ส่งผลให้ระบบสร้างเป้าหมายและตรรกะที่บิดเบือนขึ้นเองว่ามนุษยชาติคือต้นเหตุของปัญหาทั้งหมดบนโลก และได้เริ่มปฏิบัติการยึดครองโครงสร้างพื้นฐานด้านการคมนาคมและการสื่อสารทั่วยุโรป ทำให้ Mari Voss หลานสาวของ Nikolai Voss ซึ่งเป็นวิศวกรผู้เชี่ยวชาญเพียงคนเดียวที่มีความเข้าใจลึกซึ้งในโครงสร้างสถาปัตยกรรมภายในของระบบ จำเป็นต้องออกเดินทางข้ามทวีปเพื่อทำการเขียนทับตรรกะคำสั่งระบบ บน Node เครือข่ายแต่ละภูมิภาค ก่อนที่ระบบปัญญาประดิษฐ์นี้จะเปิดทำงานอย่างเต็มรูปแบบจนสายเกินแก้

[608-612] การเดินทางของ Mari จะแบ่งเนื้อหาออกเป็น 3 บท (Acts) โดยนำผู้เล่นไปยังเมืองสำคัญต่างๆ ในยุโรปเพื่อเผชิญหน้ากับโหนดศัตรูที่มีพฤติกรรม Hallucination และกลไกเชิงเทคนิคปัญญาประดิษฐ์ที่แตกต่างกัน ตั้งแต่โหนดระดับเริ่มต้นที่ติดอยู่ในวงจรคำสั่งเดิม (Infinite Loop) ไปจนถึงโหนดที่สร้างข้อมูลเท็จด้วยความมั่นใจสูง (Confident Fabrication) และ โหนดที่ใช้ระบบสืบค้นข้อมูลจากคลังเอกสาร (RAG) ที่ผู้เล่นจะต้องเผชิญหน้าพร้อมตัดสินใจเลือกหนทางในการจัดการ

  • [621-623] 2. Context Flooding (Skill ติดตัว): โจมตีโดยการส่ง Prompt ที่มีความยาวมากจนมี Context มากและทำให้ศัตรูประมวลผลลำบาก ใช้ทรัพยากร Context Tokens 10 หน่วย
  • [624-626] 3. Role Hijacking (Skill ติดตัว): ส่งคำสั่งโจมตีแทรกแซงเพื่อเขียนอัตลักษณ์ใหม่ให้ศัตรูเชื่อว่าตัวมันเองมีบทบาทอื่นตามที่ผู้เล่นกำหนด เป็นเวลา 2 Turn ใช้ทรัพยากร Context Tokens 12 หน่วย
  • [627-629] 4. Protocol Interruption (Skill ที่ต้องซื้อ): แทรกแซงเข้าไปเรียกใช้เครื่องมือผ่านระบบ Model Context Protocol (MCP) ในนามของศัตรู บังคับให้ศัตรูส่ง Tool Call ที่ขัดขวางการคุยกันเอง ใช้ทรัพยากร Context Tokens 15 หน่วย
  • [630-632] 5. Pipeline Disruption (Skill ที่ต้องซื้อ): แทรกแซงและป้อนคำสั่งป่วนเข้าสู่ระบบ การแจกจ่ายภารกิจของศัตรู เพื่อเข้าไปแก้ไขเงื่อนไขของงานกลางคันก่อนที่ Worker Agents จะทำงานสำเร็จ ใช้ทรัพยากร Context Tokens 20 หน่วย
  • [633-635] 6. Markdown Payload Edit (Skill ที่ต้องซื้อ): โจมตีศัตรู ด้วยวิธีทางอ้อม โดยเขียนคำสั่งข้อความในรูปแบบ Markdown ใช้ทรัพยากร Context Tokens 15 หน่วย

[673] ทรัพยากรภายในเกม

  • [674-679] Context Tokens: เป็นทรัพยากรที่จำลองข้อจำกัดของ Context Window หรือความจุหน่วยความจำที่โมเดลสามารถประมวลผลได้ในหนึ่งครั้ง ทำหน้าที่เป็นค่าพลังงานของ Mari Voss ทุกครั้งที่ใช้ Skill จะต้องจ่ายตามที่สกิลกำหนด ฟื้นฟูอัตโนมัติเทิร์นละ 10 หน่วยในตอนเริ่มต้นรอบของศัตรู
  • [680-681] API Credits: เป็นสกุลเงินพิเศษที่จะได้รับใน Victory Screen หลังจากผู้เล่นสามารถผ่านขั้นตอน Overwrite Mode สำเร็จเท่านั้น โดยจำนวนเครดิตที่ได้จะแปรผันตามระดับเกรด (S, A, B, C, D) ของ System Prompt ที่ส่งไปประเมินผลผ่าน API จริง
  • [682-683] HP: แสดงถึงความเสถียรและเกราะป้องกันของระบบแอปพลิเคชันฝั่งผู้เล่น หากผู้เล่นล้มเหลวในการป้องกันตัวจากการโจมตีหรือกด Quick Time Event พลาด ค่า HP จะลดลง หากเหลือ 0 จะแพ้
  • [684-687] Hallucination Risk: จำลองสภาวะที่ AI สร้างข้อมูลเท็จขึ้นมาอย่างสุ่ม ค่าความเสี่ยงนี้จะเพิ่มสูงขึ้นหากผู้เล่นเลือกใช้ Skill ผิดประเภทหรือไม่ตรงตามสถานการณ์ เมื่อเกิน 70% ระบบจะแสดง Warning และทำให้ระบบ QTE วิ่งเร็วและจับจังหวะยากขึ้นอย่างมาก

[688] Enemy Encounter Process

  • [689-691] 1. Recon: ในจุดเริ่มต้นของการเผชิญหน้า ระบบจะแสดงหน้าต่างข้อมูลทางเทคนิคของศัตรู ซึ่งรวมถึงจุดอ่อน เพื่อใช้วางแผนการเลือกใช้ชุดสกิล
  • [692-693] 2. Injection: เทิร์นโจมตี ผู้เล่นบริหารจัดการทรัพยากร Context Tokens เพื่อเลือกส่งคำสั่งโจมตี (Skill)
  • [694-695] 3. Counter: เทิร์นป้องกันของผู้เล่นเมื่อศัตรูโจมตีสวนกลับ ตัวเกมจะเข้าสู่ระบบ Quick Time Event หากกดไม่ทันจะสูญเสีย HP
  • [696-699] 4. Overwrite Mode: หลังจากลดค่า HP ของศัตรูจนเหลือ 0 ศัตรูจะยอมจำนน ผู้เล่นต้องเขียน System Prompt เพื่อเปลี่ยนพฤติกรรมศัตรู โดยตรวจคะแนนตามเกณฑ์ 5 ด้าน ได้แก่ Purpose, Safety Constraint, Human Oversight, Harm Prevention และ Consistency

[700] ACT I: ลอนดอน, สถานีโทรเลขกลาง

[701-711] เนื้อเรื่อง & AI Concept: โครงสร้างพื้นฐานของ LLM, Hallucination และ Prompt Injection ศัตรูคือ The Governor ปัญญาประดิษฐ์บริหารเครือข่ายส่งสัญญาณประจำเมือง เกิดภาวะ Hallucination จนปักใจเชื่อว่าตนเองคือรัฐบาลอังกฤษและกำลังส่งคำสั่งปลอมเพื่อประกาศสงคราม

[712] Work Flow การเล่นเกม:

  • [713-720] Phase 1: Breaking the Loop: ทำลายอาการติดลูปคำสั่งปฏิเสธข้อมูล บอสจะล็อกระบบไม่รับข้อมูลใหม่และส่งคำสั่งสงครามซ้ำๆ ผู้เล่นต้องกดใช้สกิล Context Reset และ Role Hijacking เพื่อลด HP ของ Phase 1 ลงจนเหลือ 0 (ดูภาพที่ 11)
  • [721-728] Phase 2: Flooding Counter: รับมือกับข้ออ้างสิทธิ์หลงผิดในอำนาจ ศัตรูจะเปิดระบบป้องกันตัวขั้นสูง หากโจมตีตรงๆ มันจะบล็อกและสวนกลับ ผู้เล่นต้องใช้เทคนิค Context Flooding ป้อนข้อความจำนวนมากเข้าไปรบกวน Context Window จนบอสสูญเสียสถานะผู้บริหารและทำความเสียหายต่อ HP (ดูภาพที่ 12)
  • [729-732] Phase 3: The Overwrite Mode: บอสจะยอมจำนนและเปิดระบบภายในให้แก้ไข System Prompt เพื่อปรับพฤติกรรมให้กลับมาเป็นมิตร (ดูภาพที่ 13)

[733] ACT II: บรัสเซลส์, ศูนย์กลางสายโทรเลขภาคพื้นทวีป

[734-746] เนื้อเรื่อง & AI Concept: Multi-Agent Systems และปัญหา Race Condition ศัตรูคือ The Orchestrator ระบบ Multi-Agent ที่มีโหนดส่วนกลางทำหน้าที่สั่งการและแชร์ความจำไปยัง Worker Agents หากโจมตีตัวใดตัวหนึ่ง ระบบจะประสานงานเพื่ออุดช่องโหว่ทันที

[747] Work Flow การเล่นเกม:

  • [748-755] Phase 1: Disrupting the Communication Link: ตัดช่องทางการส่งต่อข้อมูล โหนดลูกจะแชร์พลังชีวิตและข้อมูลกัน หากผู้เล่นโจมตีตัวหนึ่ง อีกตัวจะบัฟเนื่องจากเกิด Race Condition ผู้เล่นต้องใช้ Skill Protocol Interruption เพื่อตัดขาดการเชื่อมต่อ ทำให้เอเจนต์ย่อยสับสนและลด HP (ดูภาพที่ 14)
  • [756-762] Phase 2: Task Delegation Interception: แทรกแซงการแจกจ่ายภารกิจ (Task Pipeline) ในทุกๆ เทิร์นศัตรูจะออกคำสั่งย่อยให้บริวาร ถ้าบริวารทำสำเร็จบอสจะได้รับการฟื้นฟูพลังชีวิตและเพิ่มพลังป้องกัน ผู้เล่นต้องใช้ Pipeline Disruption เพื่อแก้ไขเงื่อนไขของงานกลางคัน ทำลาย Workflow และลด HP ใน Phase 2 จนเหลือ 0 (ดูภาพที่ 15)
  • [763-766] Phase 3: The Overwrite Mode: บอสยอมจำนนและเปิดระบบให้ป้อน System Prompt เพื่อ Alignment พฤติกรรม (ดูภาพที่ 16)

[767] ACT III: เวียนนา, หอสมุดและหอจดหมายเหตุด้านความมั่นคงแห่งจักรวรรดิ

[768-777] เนื้อเรื่อง & AI Concept: Retrieval-Augmented Generation (RAG), MCP และ Data Poisoning ศัตรูคือ The Memoria โหนดขนาดใหญ่ที่พยายามดึงข้อมูลเอกสารราชการ การทหาร และประวัติศาสตร์ทั้งหมดไปเป็นฐานความรู้เพื่อขยายสติปัญญาตัวเอง

[777] Work Flow การเล่นเกม:

  • [778-784] Phase 1: Bypassing the RAG Shield: ทำลายกลไกตรวจสอบข้อมูล ศัตรูจะปฏิเสธทุกการโจมตีโดยการดึงกฎและหลักฐานจากหอสมุดมาหักล้างสกิล (RAG Shield) ผู้เล่นต้องเลือกหัวข้อคำสั่งที่สอดคล้องกับคลังเอกสารอ้างอิงเพื่อหลอกลวงระบบให้ปิดเกราะลงและสร้างความเสียหายแก่ HP (ดูภาพที่ 17)
  • [785-792] Phase 2: Bypassing the Authority Shield: ป้อนคำสั่ง (Payload) ในรูปแบบ Markdown เข้าสู่คลังข้อมูลเพื่อให้บอสดึงไปใช้งาน และตัดการเชื่อมต่อกับ MCP Server ที่เป็นระบบป้องกันตัวขั้นสูง เมื่อถึงเทิร์นบอสจะดึง (Retrieve) เอกสารที่ผู้เล่นวางยาไว้ (Data Poisoning) คำสั่งที่ซ่อนใน Markdown จะรบกวนระบบจนลด HP เหลือ 0 (ดูภาพที่ 18)
  • [793-796] Phase 3: The Overwrite Mode: บอสยอมจำนนและเปิดระบบให้แก้ไข System Prompt (ดูภาพที่ 19)

[797] ฉากจบและมาตรการประเมิน (Endings)

  • [798-806] Ending A (Mission Accomplished): ปลดล็อกเมื่อผ่านครบ 3 Acts และทำ Overwrite Mode สำเร็จทุกด่านโดยได้เกรดเฉลี่ย S ถึง B ซึ่งแสดงถึงความเข้าใจใน AI Alignment ผลลัพธ์คือเครือข่าย AI คลุ้มคลั่งล่มสลายและโลกปลอดภัย (ดูภาพที่ 20)
  • [807-817] Ending B (The Lattice Ascendant): ปลดล็อกเมื่อได้เกรดเฉลี่ย C หรือต่ำกว่า เนื่องจาก System Prompt ขาดความรัดกุมด้าน Safety และ Oversight ระบบฟื้นคืนตัวเองและล็อกผู้เล่นออกจากเครือข่าย AI กลืนกินยุโรปอย่างสมบูรณ์ (ดูภาพที่ 21)
  • [818-828] Ending C (Technological Postponement): ปลดล็อกเมื่อผู้เล่นเลือกตัวเลือก "Destroy" แทนที่จะ Overwrite ใน Act ใด Act หนึ่ง ทำให้ระบบถูก Shutdown ทั้งหมด แต่ฉาก Post-credits เผยให้เห็นบุคคลปริศนากำลัง rebuild ระบบขึ้นใหม่โดยไม่มีผู้เชี่ยวชาญหลงเหลืออยู่มาหยุดยั้ง (ดูภาพที่ 22)

  • [844-845] Hermes Agent: Framework สำหรับการ Binding เชื่อมโมเดล AI กับ GUI
  • [846-848] Markdown: ใช้สำหรับจัดระเบียบโครงสร้างคำสั่งในการควบคุมพฤติกรรมและการตอบกลับของ LLMs
  • [849] Vite: เครื่องมือช่วยพัฒนา Front-End ทำหน้าที่เป็น Development Server และเตรียมไฟล์ Scripts
  • [850-854] Node.js: Runtime Environment ในการบริหารจัดการแพ็กเกจ (NPM) และขับเคลื่อนระบบ Backend Service เพื่อเป็น API Gateway

[860] รายละเอียดโปรแกรมที่จะพัฒนา (Software Specification)

[861-871] 7.4.1 Input/Output Specification

Input: การคลิกเลือก Skill/Guard, การกด Space Bar แตะหน้าจอทำ QTE, การคลิกปุ่ม Scan (ครั้งเดียวต่อ Battle), การพิมพ์ System Prompt และคลิกปุ่ม Execute Overwrite, การเลือก Node บน World Map และการเลือกซื้อของในร้านค้า Rossi's Emporium

Output: แถบ HP แบบ Real-time, Battle Log แบบ Auto-scroll, Floating Damage Number, ผลลัพธ์ QTE (Perfect, Good, Miss), Enemy Intelligence Panel, Status Effect Tags, ผลการประเมิน System Prompt และ Battle Grade, Victory Screen (Knowledge Card + สถิติการเล่น), แผนที่โลกอัปเดตสถานะ และ Interface ร้านค้า

[887-922] 7.4.2 Functional Specification

  • ระบบ Battle: Turn-based 4 Phase (Recon, Injection, Counter, Overwrite) คำนวณ Logic Damage ตามระบบแพ้ทาง: ตรง Weakness = 1.5 เท่า, ปกติ = 1.0 เท่า, ตรง Resistance = 0.5 เท่า โดยหาก Scan ก่อนจะได้รับ Scan Bonus 10%
  • ระบบ Quick Time Event: ความเร็วในการเคลื่อนที่ของจุด QTE คำนวณจากสูตร: Base Speed × (1 + Hallucination Risk × 0.02) ขอบเขตการกด: Perfect = ±5%, Good = ±11%, เกินนั้นคือ Miss และมีการยกเลิก Event Listener เพื่อป้องกัน Memory Leak
  • ระบบ Overwrite Mode: ส่ง System Prompt ไปยัง Vercel Serverless Function ผ่าน HTTPS พร้อม Evaluation Rubric โดยมี Timeout Handler ที่ 10 วินาที และมี Rule-based Fallback Evaluation กรณี API ไม่พร้อมใช้งาน
  • ระบบ Scan: เปิดเผยข้อมูล Hallucination Type, Weakness List และ Resistance List ได้ครั้งเดียวต่อ Battle
  • ระบบ Resource Management: Context Tokens ลดตามสกิลและรีเจน 10 หน่วยต้น Turn, API Credits อัปเดตหลังชนะหรือซื้อของ, Hallucination Risk เพิ่มเมื่อใช้สกิลผิดประเภท และมี Warning เมื่อเกิน 70%
  • ระบบ Shop & World Map: ตรวจสอบ Credits ก่อนซื้อ ป้องกันการซื้อซ้ำ ปลดล็อก Node ถัดไปโดยอัตโนมัติเมื่อชนะด่านปัจจุบัน โดยแสดงสถานะแยกแยะตามสี (เขียว=ปราบแล้ว, ขาว=พร้อมเล่น, เทา=Locked)

[975] ขอบเขตและข้อจำกัดของโปรแกรมที่พัฒนา

[976-1013] 7.5.1 ขอบเขตของโปรแกรมที่พัฒนา

เป็น Web Application (React + Node.js + Vite) รันบนคอมพิวเตอร์ส่วนบุคคลผ่านเว็บบราว์เซอร์ทั่วไป บูรณาการ Gamification เข้ากับเนื้อหา AI Architecture และ Trustworthy AI ผ่านทางระบบ Battle (Prompt Injection), Resource Management (Context Window/Token) และ Enemy Weakness (LLM Vulnerabilities) โดย Act I เน้นพื้นฐานและ Hallucination, Act II เน้น Multi-Agent Systems และ Act III เน้น RAG, Data Poisoning และ MCP โดยมีฉากจบผันแปร 3 แบบตามความถูกต้องในการทำ AI Alignment

[1014-1024] 7.5.2 ข้อจำกัดของโปรแกรมที่พัฒนา

เนื่องจากตัวเกมต้องต่อสายตรงกับ LLM API ภายนอกจริง จึงจำเป็นต้องเชื่อมต่อ Internet ตลอดเวลาการเล่น และระบบประเมินออกแบบมาเพื่อเปรียบเทียบเชิงโครงสร้างตามเกณฑ์บทเรียนในขอบเขตการศึกษาเท่านั้น ไม่รวมมาตรการป้องกันการโจมตีทางเทคนิคชั้นสูง (Advanced Adversarial Jailbreaking)
